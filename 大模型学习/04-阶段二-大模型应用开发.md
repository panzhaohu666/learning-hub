### 手机摸鱼 · 上午 30 分钟
阅读主题：装饰器（Decorator）—— Python 最优雅的特性之一

> **🦸 装饰器就像给函数穿装备**。想象你的函数是一个战士，裸装上阵只能平 A。你给它穿上一件"计时器披风"→ 每次攻击自动记录用时。再穿上一双"重试靴子"→ 攻击失败自动再来一次。最妙的是——**战士本身的技能没有变**，只是戴上装备后更强了。这就是装饰器：不改变原函数代码，但让函数变得更强。

核心知识点

1. 装饰器是什么？

装饰器本质上是一个函数，它接收一个函数作为参数，
返回一个新的函数。用于在不修改原函数代码的情况下，
给函数添加额外功能。

最简单的装饰器：
```python
def my_decorator(func):
    def wrapper():
        print("函数执行前")
        func()
        print("函数执行后")
    return wrapper

@my_decorator
def say_hello():
    print("Hello!")

say_hello()
# 输出：
# 函数执行前
# Hello!
# 函数执行后
```

2. 装饰器的核心语法糖：@

@my_decorator
def foo(): ...

等价于：foo = my_decorator(foo)

装饰器在函数定义时就执行了（不是在调用时），它替换了原函数。

3. 带参数的装饰器

装饰器本身也可以接受参数。这时需要三层嵌套：

```python
def repeat(n):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for _ in range(n):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(3)
def greet(name):
    print(f"Hello {name}!")

greet("World")  # 打印 3 次
```

4. 装饰器的实际应用场景
- 日志记录：自动记录函数调用时间、参数、返回值
- 性能计时：测量函数执行时间
- 权限校验：检查用户是否有权限执行某个操作
- 缓存：缓存函数结果，避免重复计算
- 重试：函数失败后自动重试

> 🚨 **Don't Skip This**：装饰器的"三层嵌套"（repeat→decorator→wrapper）是很多初学者卡住的地方。记一个口诀：**"外层收参数，中层收函数，内层收函数参数"**。外层 `repeat(n)` 收装饰器自己的参数，中层 `decorator(func)` 收被装饰的函数，内层 `wrapper(*args, **kwargs)` 收被装饰函数的参数。

```python
import time
from functools import wraps

def timer(func):
    """装饰器：打印函数执行时间"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} 执行耗时: {elapsed:.4f} 秒")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(0.5)
    return "done"

slow_function()  # 输出：slow_function 执行耗时: 0.5001 秒
```

任务 2：重试装饰器（API 调用失败自动重试）
```python
def retry(max_attempts=3, delay=1):
    """装饰器：失败后自动重试"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {attempt} 次尝试失败: {e}")
                    if attempt < max_attempts:
                        time.sleep(delay)
                    else:
                        raise  # 所有重试都失败，抛出异常
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.5)
def unstable_api_call():
    import random
    if random.random() < 0.7:  # 70%概率失败
        raise ConnectionError("网络超时")
    return "成功！"

# 测试：应该会自动重试直到成功或超过3次
print(unstable_api_call())
```

### 手机摸鱼 · 上午 30 分钟
阅读主题：迭代器与生成器

> **🚰 生成器像水龙头——你需要时才出水，不需要时关着。** 如果列表是把一整桶水放在你面前（占地方），生成器就是一根水管接到水库——你拧开水龙头（调用 next()），出来一滴水（yield 一个值），用完关掉，下一滴需要时再拧。处理 10GB 的日志文件？列表方案直接崩，生成器方案轻松搞定。

核心知识点

1. 迭代器（Iterator）

实现了 __iter__() 和 __next__() 方法的对象。
for 循环的底层就是不断调用 __next__() 直到抛出 StopIteration。

```python
class CountDown:
    def __init__(self, start):
        self.current = start
    def __iter__(self):
        return self
    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

for n in CountDown(5):
    print(n)  # 5, 4, 3, 2, 1
```

2. 生成器（Generator）—— 更优雅的迭代器

用 yield 关键字的函数就是生成器。每调用一次 yield，
函数暂停并返回值，下次 next() 时从暂停处继续。

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for num in countdown(5):
    print(num)  # 5, 4, 3, 2, 1
```

3. 生成器 vs 列表的区别（这是关键！）

**列表：一次性把所有数据加载到内存**
**生成器：每次只"产生"一个数据，用完了就不占内存了**

```python
# 列表方式：1亿个数字全部加载到内存 → 可能撑爆
nums_list = [i for i in range(100_000_000)]

# 生成器方式：每次都只产出一个数字 → 内存几乎不占
nums_gen = (i for i in range(100_000_000))
```

4. 真实场景：处理大文件
```python
def read_large_file(filepath):
    """逐行读取大文件（几GB的日志文件也能处理）"""
    with open(filepath, 'r') as f:
        for line in f:  # 文件对象本身就是迭代器
            yield line.strip()

# 10GB 的日志文件也不怕，因为一次只在内存中存一行
for line in read_large_file("huge_log.txt"):
    if "ERROR" in line:
        print(f"发现错误：{line[:100]}")
```

5. yield from：委托给子生成器
```python
def chain_generators(*gens):
    for gen in gens:
        yield from gen  # 等价于：for item in gen: yield item

gen1 = (x for x in range(3))
gen2 = (x for x in range(3, 6))
for n in chain_generators(gen1, gen2):
    print(n)  # 0,1,2,3,4,5
```

```python
def batch_chat(prompts, model="qwen2:0.5b"):
    """输入一个 Prompt 列表，逐个调用 LLM 并 yield 结果。
    用生成器而不是一次性返回所有结果：
    - 如果第1个结果就够了，不用等后面的
    - 如果某个失败了，可以决定是否继续"""
    from openai import OpenAI
    client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    for i, prompt in enumerate(prompts):
        try:
            response = client.chat.completions.create(
                model=model,
                messages=[{"role": "user", "content": prompt}]
            )
            yield {"index": i, "prompt": prompt[:50], "result": response.choices[0].message.content}
        except Exception as e:
            yield {"index": i, "prompt": prompt[:50], "error": str(e)}

# 使用：逐个处理结果
prompts = ["介绍Python", "介绍Java", "介绍Go"]
for result in batch_chat(prompts):
    print(f"第{result['index']+1}个结果：{result.get('result', result.get('error'))[:50]}")
```

阅读主题：用面向对象封装 LLM 调用

> **🍳 类就像做菜模板**。你定义好"宫保鸡丁"的模板（类）——食材是什么、步骤是什么、火候多少。每次实例化（创建对象）就是实际做一盘宫保鸡丁——鸡丁（gongbao_dish_1）、鸡丁（gongbao_dish_2）虽然来自同一个模板，但可以有不同的辣度、不同的花生量。同样的，`QwenClient` 和 `DeepSeekClient` 都来自同一个 `LLMClient` 模板，但一个连本地、一个连云端——调用方式一模一样。

核心知识点

1. 为什么要把 LLM 调用封装成类？

目前你的代码中，每次调用 API 都要：
```python
from openai import OpenAI
client = OpenAI(base_url="...", api_key="...")
response = client.chat.completions.create(model="...", messages=..., temperature=...)
```

问题：
- 代码重复
- 换了模型要改很多地方
- 日志、重试、超时等逻辑散落各处
- 测试困难

解决方案：设计一个 LLMClient 基类，子类各自实现不同模型的调用。

2. 设计方案

```python
class LLMClient:
    """LLM 客户端基类：定义统一接口"""

    def chat(self, messages, **kwargs):
        raise NotImplementedError

    def chat_with_retry(self, messages, max_retries=3, **kwargs):
        """带重试的 chat 方法（所有子类自动继承）"""
        for attempt in range(max_retries):
            try:
                return self.chat(messages, **kwargs)
            except Exception as e:
                if attempt == max_retries - 1:
                    raise
                time.sleep(2 ** attempt)  # 指数退避

class QwenClient(LLMClient):
    """本地 Qwen 模型客户端"""

    def __init__(self, host="localhost", port=11434):
        self.client = OpenAI(base_url=f"http://{host}:{port}/v1", api_key="ollama")

    def chat(self, messages, model="qwen2:0.5b", temperature=0.7, **kwargs):
        response = self.client.chat.completions.create(
            model=model, messages=messages, temperature=temperature, **kwargs
        )
        return response.choices[0].message.content

class DeepSeekClient(LLMClient):
    """DeepSeek API 客户端"""

    def __init__(self, api_key):
        self.client = OpenAI(api_key=api_key, base_url="https://api.deepseek.com")

    def chat(self, messages, model="deepseek-chat", temperature=0.7, **kwargs):
        response = self.client.chat.completions.create(
            model=model, messages=messages, temperature=temperature, **kwargs
        )
        return response.choices[0].message.content
```

现在切换模型只需改一行：
```python
# llm = QwenClient()
llm = DeepSeekClient(api_key="xxx")
reply = llm.chat_with_retry([{"role":"user","content":"Hello"}])
```

3. OOP 的三大特性在这里的体现

封装（Encapsulation）：客户端内部细节（base_url, api_key）对外隐藏
继承（Inheritance）：子类复用 chat_with_retry 等通用逻辑
多态（Polymorphism）：QwenClient 和 DeepSeekClient 可以互换使用

> 🚨 **Don't Skip This**：OOP 不是"为了用类而用类"。如果你只有一个模型、不需要切换，`def chat()` 函数就够了。类的好处只有在"多个相似但不同的东西需要统一接口"时才体现——这正是 LLM 开发的场景：不同模型、不同 API，但调用方式应该一样。

阅读主题：asyncio —— Python 的异步编程

> **🍽️ 异步像饭店点菜——你点了三道菜，哪道先好先上哪道。** 同步（一个人）是这样的：你点宫保鸡丁 → 厨师开始做 → 你站在厨房门口等 → 10 分钟后端出来 → 你再点麻婆豆腐 → 又等 10 分钟 → 你再点酸辣汤 → 又等 10 分钟。三道菜花了 30 分钟。异步是这样的：你一次性点了三道菜 → 厨师同时开工 → 8 分钟后麻婆豆腐好了先上 → 10 分钟后宫保鸡丁好了 → 12 分钟后酸辣汤好了。三道菜只花了 12 分钟。

核心知识点

1. 同步 vs 异步（用餐厅点菜来理解）

同步（一个人）：你点菜 → 等菜做好 → 吃 → 点下一道菜 → 等 → 吃...
异步（一个人）：你点 3 道菜 → 菜在做的时候你看手机 → 哪道先好先吃哪道

同步代码等的是 CPU，异步代码等的是"IO"（网络请求、文件读写）。

2. 三个关键字：async / await

async def：定义一个协程（coroutine），可以暂停和恢复
await：暂停当前协程，等待另一个协程完成，这期间其他协程可以运行

```python
import asyncio

async def fetch_data(url):
    print(f"开始请求 {url}")
    await asyncio.sleep(2)  # 模拟网络请求（不阻塞其他协程）
    print(f"完成请求 {url}")
    return f"来自 {url} 的数据"

async def main():
    # 并发请求 3 个 URL：总共只花 2 秒
    results = await asyncio.gather(
        fetch_data("url1"),
        fetch_data("url2"),
        fetch_data("url3"),
    )
    print(results)

asyncio.run(main())
```

3. 为什么 LLM 开发需要 asyncio？

场景 1：并发调用多个 API
- 比如同时让 GPT 和 Claude 回答同一个问题，对比结果
- 同步方式：等 GPT 回答完 → 再等 Claude回答 → 总时间 = T1 + T2
- 异步方式：同时发送两个请求 → 总时间 = max(T1, T2)

场景 2：批量推理
- 一次处理 100 个问题，逐个调用太慢了
- 异步并发 10 个同时跑

场景 3：构建 API 服务
- FastAPI 基于 asyncio，能同时处理多个用户请求

4. asyncio 的核心概念速查
asyncio.sleep(n)：异步等待 n 秒（不阻塞）
asyncio.gather(*tasks)：并发运行多个协程
asyncio.create_task()：创建后台任务
asyncio.Semaphore(n)：限制并发数（防止打爆 API 限流）

```python
import asyncio
import time
from openai import AsyncOpenAI  # 注意是 AsyncOpenAI

# 同步版本
def sync_compare(prompt):
    client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    models = ["qwen2:0.5b", "qwen2:1.5b"]
    results = []
    for model in models:
        resp = client.chat.completions.create(
            model=model,
            messages=[{"role":"user","content":prompt}]
        )
        results.append(resp.choices[0].message.content)
    return results

# 异步版本
async def async_compare(prompt):
    client = AsyncOpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
    models = ["qwen2:0.5b", "qwen2:1.5b"]

    async def call_one(model):
        resp = await client.chat.completions.create(
            model=model,
            messages=[{"role":"user","content":prompt}]
        )
        return model, resp.choices[0].message.content

    # 并发调用两个模型
    results = await asyncio.gather(call_one(models[0]), call_one(models[1]))
    return results

# 测速
start = time.perf_counter()
sync_compare("一句话介绍Python")
print(f"同步耗时: {time.perf_counter() - start:.2f}s")

start = time.perf_counter()
asyncio.run(async_compare("一句话介绍Python"))
print(f"异步耗时: {time.perf_counter() - start:.2f}s")
# 异步应该快接近一倍
```

核心知识点

1. 为什么 NumPy？

Python 的原生 list 做数学运算又慢又难用：
```python
# 原生：把两个列表对应元素相加
a = [1, 2, 3]
b = [4, 5, 6]
# a + b → [1,2,3,4,5,6] 不是我们要的！
result = [x+y for x,y in zip(a,b)]  # 麻烦
```

NumPy 数组（ndarray）：
```python
import numpy as np
a = np.array([1, 2, 3])
b = np.array([4, 5, 6])
a + b  # → array([5, 7, 9]) 简单！
```

而且 NumPy 用 C 实现，比 Python 快 100+ 倍。

5. 广播（Broadcasting）—— NumPy 最精妙的设计
不同形状的数组做运算时，NumPy 自动扩展维度。
规则：从右往左比较维度，相同或有一方为 1 就兼容。

```python
# (3, 4) 的矩阵 + 一个长度为 4 的向量
matrix = np.ones((3, 4))           # shape (3, 4)
vector = np.array([1, 2, 3, 4])   # shape (4,)
result = matrix + vector            # shape (3, 4)
# vector 被"广播"成 (3, 4)，然后相加
```

**🧩 广播类比**：就像老师对着全班 30 个学生说"每人加 5 分"——"5 分"这个标量被自动"广播"到了每个学生身上。NumPy 的广播就是这个原理，只是可以沿任意维度扩展。

```python
def clean_pipeline(df):
    print(f"原始数据: {len(df)} 行")

    # 1. 去重
    df = df.drop_duplicates()
    print(f"去重后: {len(df)} 行")

    # 2. 处理异常值（pm25 不可能为负）
    df['pm25'] = df['pm25'].apply(lambda x: np.nan if x < 0 else x)

    # 3. 填充缺失值（用该城市的中位数填充）
    df['pm25'] = df.groupby('city')['pm25'].transform(
        lambda x: x.fillna(x.median())
    )

    # 4. 添加衍生特征
    df['hour'] = df['date'].dt.hour
    df['month'] = df['date'].dt.month
    df['is_weekend'] = df['date'].dt.dayofweek >= 5

    print(f"清洗后: {len(df)} 行")
    return df

df_clean = clean_pipeline(df)
```

```python
class PersistentChatBot:
    def __init__(self, llm_client):
        self.llm = llm_client
        self.mongo = MongoClient("mongodb://localhost:27017").llm_app.conversations
        self.current_session = None

    def chat(self, user_id, message):
        # 加载最近 20 条消息作为上下文
        recent = list(self.mongo.find(
            {"user_id": user_id},
            {"messages": {"$slice": -20}}
        ).sort("created_at", -1).limit(1))

        history = recent[0]["messages"] if recent else []

        # 调用 LLM
        reply = self.llm.chat(history + [{"role": "user", "content": message}])

        # 存储
        self.mongo.update_one(
            {"user_id": user_id},
            {"$push": {"messages": {
                "$each": [
                    {"role": "user", "content": message},
                    {"role": "assistant", "content": reply}
                ]
            }}},
            upsert=True  # 不存在则创建
        )
        return reply
```

### 星期二
动态 Few-shot 选择
手机摸鱼：
静态 Few-shot：3 个固定示例 → 如果示例和目标输入不相关，反而误导模型
动态 Few-shot：根据输入特征从示例库中选最相似的 → 每次都精准匹配

核心代码：
```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

class DynamicFewShot:
    def __init__(self, examples):
        """examples: [{"input":"...", "output":"..."}, ...]"""
        self.examples = examples
        self.vectorizer = None
        self.example_vectors = None

    def build_index(self):
        texts = [ex["input"] for ex in self.examples]
        self.vectorizer = TfidfVectorizer()
        self.example_vectors = self.vectorizer.fit_transform(texts)

    def select(self, query, k=3):
        query_vec = self.vectorizer.transform([query])
        similarities = cosine_similarity(query_vec, self.example_vectors)[0]
        top_k = similarities.argsort()[-k:][::-1]
        return [self.examples[i] for i in top_k]

# 示例库（情感分类的标注数据）
examples = [
    {"input": "等待2小时，太失望了", "output": "负面"},
    {"input": "性价比超高，下次还来", "output": "正面"},
    {"input": "环境还行，服务一般", "output": "中性"},
    # ... 更多示例
]

selector = DynamicFewShot(examples)
selector.build_index()
relevant = selector.select("物流太慢了，包装也破了", k=2)
# 会选出最相似的 2 个负例，而不是随机选
```

### 星期四
Prompt 自动化评估
手机摸鱼：
Prompt 质量不能靠"感觉"，要做定量对比。
评估方法：准备测试集 → 多种 Prompt 分别跑 → 用规则或 LLM 打分

```python
def evaluate_prompts(prompt_configs, test_cases, client):
    """自动评估多个 Prompt 的效果"""
    results = []
    for config in prompt_configs:
        scores = []
        for case in test_cases:
            prompt = config["template"].format(**case["input"])
            response = client.chat.completions.create(
                model="deepseek-chat",
                messages=[{"role": "user", "content": prompt}],
                temperature=0
            ).choices[0].message.content

            # 用另一个 LLM 当裁判：根据期望关键词打分
            judge_prompt = f"""
            评估这个回答（1-5分）：
            任务：{case['description']}
            回答：{response}
            期望包含：{case['expected_elements']}
            只输出分数。
            """
            judge_resp = client.chat.completions.create(
                model="deepseek-chat",
                messages=[{"role": "user", "content": judge_prompt}],
            )
            scores.append(int(judge_resp.choices[0].message.content.strip()))

        results.append({
            "name": config["name"],
            "avg_score": sum(scores) / len(scores),
            "scores": scores
        })
    return sorted(results, key=lambda x: x["avg_score"], reverse=True)
```

```python
class PromptOptimizer:
    def __init__(self, task_desc, test_cases, client):
        self.task_desc = task_desc
        self.cases = test_cases
        self.client = client
        self.history = []

    def iterate(self, current_prompt, n=3):
        for i in range(n):
            score = self._evaluate(current_prompt)
            self.history.append({"iteration": i, "prompt": current_prompt, "score": score})

            # 让 LLM 分析失败案例并改进
            improvements = self._suggest_improvements(current_prompt, score)
            current_prompt = improvements

        # 返回最佳版本
        best = max(self.history, key=lambda x: x["score"])
        return best["prompt"], self.history

        return self.client.chat.completions.create(

任务描述：{self.task_desc}
原 Prompt：{prompt}

"""}],
```

### 星期五 · Dify API 集成到 Python
```python
import requests, os

class DifyClient:
    def __init__(self, api_key=None, base_url="http://localhost/v1"):
        self.api_key = api_key or os.getenv("DIFY_API_KEY")
        self.base_url = base_url

    def chat(self, query, user="default", conversation_id=""):
        """调用 Dify Chat API"""
        resp = requests.post(
            f"{self.base_url}/chat-messages",
            json={
                "inputs": {},
                "query": query,
                "user": user,
                "conversation_id": conversation_id,
                "response_mode": "blocking"
            },
            headers={"Authorization": f"Bearer {self.api_key}"}
        )
        data = resp.json()
        return data.get("answer", data)

    def chat_stream(self, query, user="default"):
        """流式调用（打字机效果）"""
        resp = requests.post(
            f"{self.base_url}/chat-messages",
            json={"query": query, "user": user, "response_mode": "streaming"},
            headers={"Authorization": f"Bearer {self.api_key}"},
            stream=True
        )
        for line in resp.iter_lines():
            if line:
                print(line.decode(), end="", flush=True)

# 使用示例
dify = DifyClient(api_key="app-xxxx")
reply = dify.chat("如何退货？")
print(reply)
```
