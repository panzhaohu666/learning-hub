# 软件设计师备考计划

> 🎯 **这不是一份「看看就行」的备考计划——这是一份9个月的训练方案。**
>
> 软件设计师考试每年有约20-30%的通过率。看起来很难对吧？但真相是：绝大多数失败的考生不是「学不会」，而是「没学完」或者「学了但没练」。这份计划的核心哲学很简单——**用每天的可执行动作，代替「我要好好学」的空洞决心。**
>
> 你每天只需要：上班路上手机摸鱼30min + 周二周四晚上各2h电脑做题 + 周六下午1.5h——每周约8h。9个月后，你会感谢每一天都没放弃的自己。

9个月 软件设计师备考计划
### 目标：2027年5月 · 上午45+下午45


前提：
- 计算机相关本科，学过但忘了不少
- 和"6个月大模型学习计划"并行执行
- 大模型每周 ~11h，软考每周 ~7h，总计 ~18h
- 只能用文字材料（手机看教材/真题/笔记，不能看视频）

### 一、考试结构速览


### 上午题
基础知识 · 75 道选择题 · 150 分钟 · 75 分（45 分合格）
分值分布（约）：
| 数据结构与算法 | 10-12 分 | ★★★ |
| 软件工程 | 10-12 分 | ★★★ |
| 面向对象技术 | 8-10 分 | ★★★ |
| 程序设计语言基础 | 6-8 分 | ★★ |
| 操作系统 | 5-7 分 | ★★ |
| 计算机组成与体系结构 | 5-7 分 | ★★ |
| 数据库 | 5-7 分 | ★★ |
| 计算机网络 | 5-7 分 | ★★ |
| 系统开发与运行 | 4-6 分 | ★ |
| 信息安全 | 3-5 分 | ★ |
| 标准化与知识产权 | 3-4 分 | ★ |
| 多媒体基础 | 2-3 分 | ☆ |
| 专业英语 | 5 分 | ☆（做真题时顺带练） |

策略：数据结构、软件工程、面向对象 3 块占 30+ 分，必须拿稳。
其他模块保基础分。多媒体和知识产权性价比低，真题混脸熟即可。

> ⚡ **「上午题=背+算，下午题=写+练」** 这是所有过来人的共识。上午题的75道选择题中，约40分靠背诵概念（软件工程、面向对象、数据库、网络等），约20分靠计算（数据结构、计组、OS的计算题），剩下15分靠英语和常识。下午题的75分（5道大题）全部靠「手写过6道以上真题」——光看答案没用，必须亲手写。

### 下午题
应用技术 · 5-6 道大题 · 150 分钟 · 75 分（45 分合格）
固定 4 道必做题（各 15 分）：
题1：数据流图（DFD）
题2：数据库设计（ER 图 + 关系模式 + SQL）
题3：UML 建模（类图/用例图/顺序图/活动图）
题4：算法题（C 语言实现 + 复杂度分析）

2 选 1（15 分）：
题5：C 语言程序设计（补全代码）
题6：Java 程序设计（补全代码 + 设计模式）

### 11月·前两周
数据流图（DFD）—— 下午题第 1 题
核心技能：
- 识别外部实体（矩形）、数据流（箭头）、加工（圆形）、数据存储（平行线）
- 顶层图 → 0 层图 → 1 层图的分解关系
- 数据流命名规则：名词或名词短语
- 常考：补齐数据流、找出错误的数据流、数据字典条目

二晚·第1周：DFD 基础概念 + 读 3 道真题答案，总结规律
四晚·第1周：自己做 2 道真题，对照答案修正
二晚·第2周：限时 30 分钟做 1 道真题
四晚·第2周：限时 30 分钟再做 1 道，总结 DFD 做题模板
六下：数据流图专项总结笔记

做题模板（形成肌肉记忆）：
1. 读题 3 分钟：标出所有外部实体和数据存储
2. 逐层分解 5 分钟：顶层→0层→1层，检查数据流守恒
3. 填写缺失 10 分钟：每个空对照上下文
4. 检查 2 分钟：父子图平衡、数据流起止点合理

### 11月·后两周 + 12月·第1周
数据库设计 —— 下午题第 2 题
核心技能：
- ER 图识别：实体（矩形）、属性（椭圆）、联系（菱形）
- 联系类型：1:1 / 1:N / M:N
- ER 图转关系模式：实体转为关系、M:N 联系转为独立关系
- 主键/外键识别
- 补充 SQL 语句（CREATE TABLE/SELECT/UPDATE/触发器）

二晚·第1周：ER图概念 + 关系模式转换规则
四晚·第1周：做 2 道真题（不限制时间，理解答案逻辑）
二晚·第2周：限时做 2 道真题（30 分钟/道）
四晚·第2周：SQL 补充题专项（创建表/查询/视图/触发器）
六下：数据库设计做题模板总结

关系模式转换口诀（背）：
实体 → 关系（属性即列，主键即主键）
M:N 联系 → 独立关系（双方主键+联系自身属性 → 联合主键）
1:N 联系 → 并入 N 端（把 1 端主键加到 N 端作外键）
1:1 联系 → 并入任一端

### 12月·后三周

- 补全类名/方法名/关系名
- 设计模式在 UML 题中的体现（策略/观察者/工厂）

二晚·第1周：用例图 + 类图专题

二晚·第3周：UML + 设计模式综合题
四晚·第3周：薄弱图类型补强
六下·每周：本周 UML 错题整理

类图关系速记（按耦合度从弱到强）：
依赖(Dependency) ←→ 虚线箭头
关联(Association) ←→ 实线（带箭头或双向）
聚合(Aggregation) ←→ 空心菱形（整体-部分，可分离）
组合(Composition) ←→ 实心菱形（整体-部分，同生共死）
泛化(Generalization) ←→ 空心三角（继承）
实现(Realization) ←→ 虚线空心三角（接口实现）

树的遍历口诀：
前序：根左右
中序：左根右
后序：左右根
层序：从上到下，从左到右

图的最短路径：
Dijkstra：单源最短路径，不能有负权边，O(n²)
Floyd：每对顶点最短路径，可以有负权边，O(n³)

### 操作系统·必背
进程状态转换：就绪 ←→ 运行 ←→ 阻塞
就绪→运行：被调度（CPU 分配）
运行→就绪：时间片用完
运行→阻塞：等待 I/O
阻塞→就绪：I/O 完成

PV 操作模板：
P(S)：S = S - 1；if S < 0 则进程阻塞
V(S)：S = S + 1；if S <= 0 则唤醒一个阻塞进程

死锁四个必要条件（缺一不可）：
互斥、请求保持、不可剥夺、循环等待

页面置换算法对比：
OPT（最佳）：理论最优，实际不可实现
LRU（最近最少使用）：性能最好但实现开销大
FIFO（先进先出）：最简单，可能有 Belady 异常
Clock：LRU 的近似，实用

### 数据库·必背
范式判断口诀：
1NF：每个属性不可再分（原子性）
2NF：非主属性完全依赖于主键（消除部分依赖）
3NF：非主属性不传递依赖于主键（消除传递依赖）
BCNF：主属性也不部分/传递依赖于候选键

SQL 关键语法：
CREATE TABLE t (id INT PRIMARY KEY, name VARCHAR(20))
SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY
INSERT INTO t VALUES (...)
UPDATE t SET ... WHERE ...
DELETE FROM t WHERE ...

### 九、和大模型计划的共存方式


你的大模型计划也在进行中（约 11h/周），两个计划如何不冲突？

1. 时间上完全隔离：
- 大模型：周一三五晚 + 周六下午前 2h
- 软考：  周二四晚 + 周六下午后 1.5h
不存在"今晚做哪个"的选择困难。

2. 内容上互有补充：
- 软考的数据结构和算法训练 → 大模型的 PyTorch 手写代码能力
- 大模型的 Python 编码训练 → 软考下午题的代码理解能力
- 软考的软件工程知识 → 大模型项目的工程化思维

3. 手机时间双重利用：
- 上午 30min：大模型阅读（当前阶段的教材/论文/源码）
- 下午 30min：软考阅读（教材/错题本/真题APP刷题）
两个脑子切换，反而减少疲劳。

4. 防止相互拖累：
- 大模型的阶段里程碑不变，只是进度变成原来的 60%
- 软考有明确的考试日期，倒逼进度
- 如果某周大模型遇到难点，可以临时把周四晚上也给它，
周六软考时间补回来——灵活调配。

### 十、防崩预案


同时推进两个计划，最大的风险不是"学不会"，是"坚持不下去"。

1. 允许某个计划暂停一周，但不允许同时停。
- 大模型遇到卡点？这周软考占 3 个晚上，大模型只保周六。
- 软考某模块太枯燥？这周多做大模型，软考只刷手机真题。

2. 软考的最小可交付：
- 每天手机刷 10 道上午真题（10 分钟够用）
- 每周至少做 1 套下午题

3. 利用两个计划的"节奏差"：
- 大模型需要大块时间思考和编码（一三五晚上）
- 软考更适合碎片化积累（手机刷题 + 周二四晚上做题）
- 一松一紧，互为调节

4. 考试前 2 周：大模型暂停，全力冲刺软考。
十一、6 个容易踩的坑

> 🚨 **以下是无数前辈用「再来一年」的代价换来的教训。每一条都值3个月时间。**

1. ❌ 忽视下午题，只看上午选择题。
上午题 45 分就及格确实容易，但下午题 45 分才是真正的坎。
很多上午 60+ 的人下午挂了。阶段二必须认真练下午题。

2. ❌ 只看不写。下午题是"写"出来的，不是"看"出来的。
DFD、ER图、UML 图必须亲手画。算法题必须亲手补全代码。
对答案时不要"看看差不多就行"，要逐字核对。

3. ❌ 追求高分。软考 45 分就过，不要花时间在偏题怪题上。
性价比低的模块（多媒体、知识产权）真题混脸熟即可。

4. ❌ 真题只做近 3 年。知识点可能重复，但覆盖面不够。
近 8 年真题都要做，才能覆盖足够的知识面。

5. ❌ 忽视上午题的计算题。上午题不全是"背诵型"选择题，
数据结构、计组、操作系统都有需要计算的题目。
比如：流水线吞吐率、Cache命中率、PV操作、页面置换缺页次数。

6. ❌ 不做模拟考场。平时不限时做和限时做完全两码事。
阶段三必须严格按考试时间做全真模拟。

### 十二、数据流图（DFD）做题模板


这是下午题第 1 题（15 分），也是最好拿分的题。
背下这个模板，每次做题都按流程来：

Step 1【3 分钟】读题，圈出关键信息
- 用笔画出来：XX系统、XX管理员、XX用户 → 这些都是外部实体
- 圈出数据存储：XX表、XX文件、XX库
- 理解业务：这个系统是干什么的？

Step 2【5 分钟】对照顶层图和 0 层图
- 顶层图：只有系统+外部实体+数据流
- 0 层图：系统内部拆分为多个加工
- 检查：顶层图的数据流必须全部出现在 0 层图中（平衡原则）

Step 3【10 分钟】逐空填写
填空题类型：
- 外部实体名称：从题干描述中找"XX用户""XX管理员"
- 数据存储名称：从题干中找"XX表""XX文件"
- 缺失的数据流：对比父图和子图，或从加工描述中推断
- 数据流命名：名词短语，如"订单信息""支付结果"

Step 4【2 分钟】检查
- 每条数据流的起止点有没有类型错误？
（数据流不能直接从数据存储到数据存储）
- 父图和子图的输入输出数据流是否一致？
