### 🎯 DFD 核心理解：快递物流系统类比

在读具体知识点之前，先建立一个全局画面——DFD本质上是描述「数据怎么在系统里流动」的一张图。

**把DFD想象成一个快递物流系统：**

| DFD元素 | 快递类比 | 考试中是什么 |
|---------|---------|-------------|
| 外部实体（矩形） | 寄件人和收件人 | 用户、管理员、外部系统——给系统输入数据或从系统接收数据的「人/组织」 |
| 加工（圆/圆角矩形） | 分拣中心 | 处理数据的动作——把输入数据变成输出数据 |
| 数据流（箭头） | 快递卡车 | 数据在元素之间的流动——卡车运的是包裹，数据流运的是数据 |
| 数据存储（平行线/开口矩形） | 仓库 | 存放数据的地方——数据暂时/永久保存在这里 |

**用这个类比一下就懂了：**

- 「用户」把「订单数据」交给「订单处理系统」（数据流：用户→加工）
- 「订单处理系统」把「订单」存入「订单表」（数据流：加工→数据存储）
- 「订单处理系统」从「商品表」读取商品信息（数据流：数据存储→加工）
- 「支付系统」告诉「订单处理系统」支付结果（数据流：外部实体→加工）

🚨 **常见陷阱：数据流的起止点必须有加工！** 就像快递不能自己从仓库飞到收件人手里——数据存储不能直接连到外部实体，数据存储之间也不能直接连。

### 手机摸鱼 · 第13周
星期一：DFD 四要素回顾（阶段一第7周学过）
外部实体（矩形）：人、组织、外部系统。必是名词短语。
加工（圆/圆角矩形）：处理数据的动作。必是动词+名词。
数据流（箭头）：数据流向。必是名词短语（不是动词！）。
数据存储（平行线/开口矩形）：存数据的地方。必是名词。

星期二：DFD 分层原则
顶层图（0层）：系统=1个加工，展示系统和外部实体的数据交换
1层图：顶层加工分解为多个子加工
平衡原则：父图的输入输出数据流 = 子图的输入输出数据流！
子图可以多出"内部数据流"，但不能多出或缺少"外部数据流"。
这是找"缺失数据流"的核心依据。

> ⚡ **平衡原则一句话版本：** 父图进什么出什么，子图也必须进什么出什么。子图内部你可以随便加数据流（细化内部逻辑），但和外部交换的数据流一个不能少、一个不能多。

星期三-四：每天读 2 道真题答案，关注答案是怎么推导"缺失数据流"的
星期五：总结 DFD 填空题的 3 种类型 + 各自的解题策略

### 🎯 DFD 三种填空题类型的详细解题策略

**类型①：补充外部实体名称（3-5分）**

题目问法：图中①处是什么外部实体？

解题三步走：
1. **在题干第一段找**——90%的外部实体在题干第一段就出现了。"XX系统为【用户】提供..."、"【管理员】可以..."
2. **看数据流方向**——从外部实体出发的箭头代表它「提供」数据，指向外部实体的箭头代表它「接收」数据
3. **验证名称是否匹配**——外部实体必须是名词短语，不能出现动词

**类型②：补充数据存储名称（3-5分）**

数据存储一定出现在两个地方：
1. **题干中的关键词：XX表、XX文件、XX库、XX单、XX记录**
2. **数据流上标注的内容**——如果一条数据流写着"订单信息"，目标数据存储大概率叫"订单表"

🚨 **陷阱：数据存储不叫「XX信息」！** 叫「XX表」或「XX文件」。信息的载体才是数据存储。

**类型③：补充缺失数据流（5-8分，分值最高！）**

这是DFD最值钱的题型。核心方法只有两个：

**方法A：父图-子图对比法（最可靠）**
- 数清楚父图中所有「外部实体↔加工」的数据流
- 数清楚子图中所有「外部实体↔加工」的数据流
- 对比：父图中有的，子图中必须也有（方向要一致！）

**方法B：题干加工描述法（最常用）**
- 题干描述：「系统将订单信息发送到仓库」→ 一定有数据流「加工→外部实体（仓库）」
- 题干描述：「用户查询订单状态」→ 一定有数据流「外部实体（用户）→加工」和「加工→外部实体（用户）」

### 🎯 如何在5分钟内画出标准DFD（考场实战流程）

考场上你的DFD图已经是题目给好的，你要做的不是从零画，而是**读图+补全**。这套流程严格计时：

**Step 1【30秒】：看清题目有几层图**
- 典型配置：一道题给你顶层图（1个加工）和0层图（多个加工）
- 先确认：需要补的题目在哪个层？

**Step 2【1分钟】：圈出所有外部实体**
- 题干第一段逐句扫，凡是人名/角色名/外部系统名都圈出来
- 技巧：外部实体名末尾常带「者/员/系统/平台」

**Step 3【1分钟】：圈出所有数据存储**
- 题干中带「表/库/文件/单/记录」的词全部圈出

**Step 4【2分钟】：逐空填写**
- 先填外部实体名（最简单，先拿分）
- 再填数据存储名
- 最后补缺失数据流（每补一条，验证起止点有没有加工）
- 🚨 **绝对禁止的数据流：** 外部实体→外部实体、数据存储→数据存储、数据存储→外部实体

**Step 5【30秒】：回查**
- 每条数据流都通过加工了吗？
- 父图的那些输入输出数据流，子图都有吗？

### 🚨 DFD 常见陷阱大全（出题人最爱挖的坑）

**陷阱1：数据流命名用动词**
❌ 数据流名叫「查询订单」 ❌ 数据流名叫「修改」
✅ 数据流名叫「订单信息」 ✅ 数据流名叫「修改后的数据」
→ 数据流的内容是「什么数据」，不是「什么操作」。动词留给加工用。

**陷阱2：把加工名称写成名词**
❌ 加工名叫「订单处理」这个太模糊——处理什么？
✅ 加工名叫「生成订单」「验证登录」「计算运费」
→ 加工=动词+名词，要能回答「对什么数据做什么操作」

**陷阱3：子图凭空多出外部数据流（违反平衡原则）**
❌ 父图中没有「用户→支付系统」的数据流，子图突然冒出来这条
→ 父图的输入输出数据流=子图的输入输出数据流，一条不能多

**陷阱4：数据存储和数据流混淆**
❌ 题干说「系统读取商品信息」→ 有人填数据存储「商品信息」
✅ 这道问的是数据流名称，填「商品信息」作为数据流名称是对的
但问的是数据存储名称，填「商品表」才对

**陷阱5：顶层图和0层图的外部实体数量不一致**
顶层图有3个外部实体，0层图必须有完全相同的3个外部实体
不能多也不能少

### 🎯 DFD 完整真题示例（带完整解题过程）

**例题1：在线购物系统**

> 题目描述：某在线购物系统的主要功能：用户浏览商品后下单，系统生成订单并通知仓库发货。管理员可查看和修改商品信息。系统与支付系统对接完成在线支付。用户可查询订单状态。

**第一步【2分钟】：圈出外部实体和数据存储**

外部实体（从题干逐句提取）：
- 「用户」→ 浏览商品、下单、查询订单 → 输入输出都涉及的实体
- 「管理员」→ 查看和修改商品信息
- 「支付系统」→ 与系统对接完成在线支付
- 「仓库」→ 系统通知仓库发货（仓库接收通知，也是外部实体！）

数据存储（从"存什么数据"推断）：
- 系统需要存储「商品信息」→ 商品表
- 系统需要存储「订单」→ 订单表
- （可能还有用户表，但题干没说就不瞎加）

**第二步【3分钟】：分析每条数据流**

以用户下订单为例，数据流路径：
- 用户 → 加工：「订单数据」（用户提交的订单内容）
- 加工 → 订单表：「订单信息」（系统保存订单）
- 加工 → 支付系统：「支付请求」（包含订单号和金额）
- 支付系统 → 加工：「支付结果」（成功/失败）
- 加工 → 仓库：「发货通知」
- 加工 → 用户：「订单确认」

**第三步【10分钟】：假设题目给出了不完整的0层图，让我们补全**

常见缺失：
- 空①：外部实体「支付系统」——题干明确提到了，图里少了
- 空②：数据存储「订单表」——订单数据存在哪里？
- 空③：缺失数据流「加工→仓库（发货通知）」
- 空④：缺失数据流「支付系统→加工（支付结果）」

**第四步【2分钟】：检查**
✓ 每条数据流都经过加工
✓ 外部实体和数据存储之间没有直接数据流
✓ 子图的外部输入输出=父图的外部输入输出


**例题2：学生选课系统**

> 题目：某学校选课系统：学生登录系统后查看可选课程列表，选择课程后系统记录选课信息并检查是否有时间冲突。教师可查看自己课程的学生名单。教务处可开设新学期课程。

Step1【圈实体】→ 学生、教师、教务处
Step2【圈数据存储】→ 课程表、选课记录表、学生表、教师表
Step3【分析】：
- 「检查时间冲突」说明要从「选课记录表」读取已有选课→数据流：选课记录表→加工
- 「开设新学期课程」教务处→加工：新课程数据，加工→课程表：课程信息
- 「查看学生名单」加工需要从选课记录表读数据，再输出给教师

常见缺失数据流：
- 选课记录表→加工（检查时间冲突时需要读取）
- 加工→课程表（教务处开设新课程时写入）
- 加工→选课记录表（学生选课成功后写入）

---

**例题3：酒店预订系统**

> 题目：酒店预订系统允许客户在线搜索空房、预订房间、取消预订。前台工作人员可为客户办理入住和退房。系统与短信平台对接，预订成功后自动向客户发送确认短信。经理可查看入住率统计报表。

Step1【圈实体】→ 客户、前台工作人员、短信平台、经理
Step2【圈数据存储】→ 房间表、预订表、入住记录表
Step3【找缺失】：

注意区分「前台办理入住」的数据流：
- 前台→加工：「客户入住请求」（身份证+预订号）
- 加工→预订表：读取预订信息（验证是否有效预订）
- 加工→入住记录表：写入入住记录
- 加工→房间表：更新房间状态（空房→已入住）

「短信平台」这一外部实体的数据流容易被漏掉：
- 加工→短信平台：「短信发送请求」（包含手机号和内容）

🚨 **陷阱：不要把「短信平台」误认为数据存储！** 短信平台是「发送短信」这个服务提供的载体，它不是一个存数据的地方，而是一个接收数据并执行动作的外部系统。判断标准：它是否对数据做处理？是→外部实体。只是存数据？是→数据存储。

### 🎯 ER图全局理解：餐厅点餐系统类比

我们把整个ER图的概念用「餐厅点餐系统」串起来，因为吃饭的流程人人熟悉：

想象你走进一家餐厅的点餐系统：
- **顾客**来到餐厅（实体：顾客）
- **服务员**拿**菜单**给顾客看（实体：服务员、菜单）
- 顾客**点菜**（联系——这是顾客和菜品之间的关系！）
- 每道菜有一个**编号、名称、价格**（属性）
- 点菜时记录**数量**（联系属性——这个属性不属于顾客，也不属于菜品，属于「点菜」这个行为本身）

现在把上面这段话翻译成ER图：

| 餐厅概念 | ER图概念 | 符号 |
|---------|---------|------|
| 顾客、服务员、菜品、订单 | 实体（Entity） | 矩形 |
| 顾客编号、菜名、价格 | 属性（Attribute） | 椭圆 |
| 「点菜」这个动作 | 联系（Relationship） | 菱形 |
| 一个顾客点多个菜 | M:N联系 | 两端标注M和N |
| 点菜时记录的数量 | 联系属性 | 连在菱形上的椭圆 |

**联系类型快速判断法：**
- **1:1**：一个顾客对应一个VIP卡 → 顾客和VIP卡是1:1
- **1:N**：一个顾客有多个订单 → 顾客和订单是1:N
- **M:N**：一个顾客点多个菜，一道菜被多个顾客点 → M:N

> ⚡ **考场判断技巧：** 拿题目中两个实体，分别问：「一个X对应几个Y？」如果答案是1和1就是1:1，1和多个就是1:N，多个和多个就是M:N。

### 手机摸鱼 · 第15周
星期一：ER 图转关系模式口诀复习

星期二：范式判断三步骤复习

> ⚡ **范式判断口诀（秒杀版）：**
> 1NF：「每个格子只有一个值」（不能一个格子里存两个电话号码）
> 2NF：「非主属性必须依赖完整主键」（主键是AB，C不能只依赖A）
> 3NF：「非主属性不能通过别人间接依赖主键」（A→B, B→C → A→C这种链条不行）
> BCNF：「主属性也不能拆」（升级版——主属性之间也不能有函数依赖）

### 🎯 SQL 填空的万能模板（数据库下午题必考）

SQL是下午数据库题的高频考点，通常占3-5分。好消息是——考的全是基础SQL，没有复杂嵌套！

**模板1：单表查询**
```sql
SELECT 列名1, 列名2 FROM 表名 WHERE 条件;
```
考点：读题中「查询XXX的YYY」→ XXX是条件(WHERE)，YYY是输出(SELECT)

**模板2：多表连接查询（高频！）**
```sql
SELECT A.列1, B.列2
FROM 表A A JOIN 表B B ON A.关联列 = B.关联列
WHERE 条件;
```
🚨 **陷阱：JOIN忘记加ON条件！** 不加ON就是笛卡尔积。

**模板3：分组统计（高频！）**
```sql
SELECT 列1, COUNT(*) FROM 表名
GROUP BY 列1
HAVING COUNT(*) > 某个值;
```
🚨 **陷阱：HAVING和WHERE分不清！** WHERE在分组前过滤行，HAVING在分组后过滤组。考试中问你「查询借书超过3本的读者」→ HAVING COUNT(*) > 3（分组后的统计条件）。

**模板4：嵌套子查询**
```sql
SELECT 列1 FROM 表A
WHERE 列2 IN (SELECT 列2 FROM 表B WHERE 条件);
```
或者用 EXISTS / = (单值子查询）

**模板5：创建表 / 定义主键外键（偶考）**
```sql
CREATE TABLE 表名 (
  列1 类型 PRIMARY KEY,
  列2 类型 NOT NULL,
  列3 类型 REFERENCES 父表(父表主键)
);
```

> 🎯 **SQL题3秒识别法：**
> 题干有「统计/每...的数量」→ GROUP BY + COUNT
> 题干有「查询...且该数据在另一张表中」→ JOIN 或 子查询
> 题干有「新建一张表」→ CREATE TABLE
> 题干有「哪些...大于/小于」→ HAVING

### 🎯 完整ER图转关系模式示例：餐厅点餐系统

**题目描述：**
某餐厅管理系统中，有以下信息：
- 顾客（顾客编号，姓名，电话）
- 菜品（菜品编号，菜名，价格，分类）
- 订单（订单编号，下单时间，总金额）
- 一位顾客可以有多个订单（1:N）
- 一个订单包含多个菜品，一道菜品可以出现在多个订单中（M:N）
- 订单中包含的每道菜品需要记录数量

**第一问：补充ER图**

实体（4个矩形）：顾客、菜品、订单、服务员（题干可能还提到服务员）
联系（3个菱形）：
- 「下单」：顾客(1) —— 订单(N)，是1:N关系
- 「包含」：订单(M) —— 菜品(N)，是M:N关系，联系属性：数量
- （如果题干提到服务员：「服务」：服务员(1) —— 订单(N)，1:N）

**第二问：ER图转关系模式——完整转换过程**

转换规则应用：

1. **「顾客」实体 → 关系模式「顾客表」**
   - 顾客（顾客编号，姓名，电话）
   - 主键：顾客编号

2. **「菜品」实体 → 关系模式「菜品表」**
   - 菜品（菜品编号，菜名，价格，分类）
   - 主键：菜品编号

3. **「订单」实体 + 1:N联系「下单」→ 合并**
   - 顾客和订单是1:N，所以把1端（顾客）的主键「顾客编号」作为N端（订单）的外键
   - 订单（订单编号，下单时间，总金额，**顾客编号**）
   - 主键：订单编号
   - 外键：顾客编号 REFERENCES 顾客(顾客编号)

4. **M:N联系「包含」→ 独立关系模式**
   - 订单和菜品是M:N，生成独立的中间表
   - 包含（**订单编号**，**菜品编号**，数量）
   - 主键：(订单编号, 菜品编号) —— 联合主键！
   - 外键：订单编号 REFERENCES 订单(订单编号)
   - 外键：菜品编号 REFERENCES 菜品(菜品编号)
   - 联系属性「数量」放在这个关系里

**最终得到4个关系模式：**
```text
顾客（顾客编号, 姓名, 电话）
菜品（菜品编号, 菜名, 价格, 分类）
订单（订单编号, 下单时间, 总金额, 顾客编号）   ← 顾客编号是外键
包含（订单编号, 菜品编号, 数量）               ← 两个都是外键+联合主键
```

> 🚨 **致命错误：M:N联系忘记生成独立关系！** 80%的考生在1:N和1:1的转换上都不会错，但M:N联系必须生成一个独立的中间表，否则会丢失信息。考试中如果真的忘了一个M:N联系的表，至少丢3分。

**第三问：补充SQL**

问题1：「查询点过『宫保鸡丁』的所有顾客的姓名和电话」
```sql
SELECT 姓名, 电话 FROM 顾客
WHERE 顾客编号 IN (
  SELECT 顾客编号 FROM 订单
  WHERE 订单编号 IN (
    SELECT 订单编号 FROM 包含
    WHERE 菜品编号 = (
      SELECT 菜品编号 FROM 菜品 WHERE 菜名 = '宫保鸡丁'
    )
  )
);
```
→ 解题思路：从内往外推。最内层找到「宫保鸡丁」的菜品编号→中间层找到包含这个菜品的订单→外层找到下这些订单的顾客。

问题2：「统计每个顾客的订单数量，只显示订单数≥2的顾客」
```sql
SELECT 顾客编号, COUNT(*) AS 订单数
FROM 订单
GROUP BY 顾客编号
HAVING COUNT(*) >= 2;
```
→ 🚨 这里用HAVING不是WHERE！因为COUNT(*)是分组后才算出来的统计值。

### 🎯 数据库下午题常见失分点

**失分点1：主键选错**
❌ 选了一个不能唯一标识元组的属性做主键
✅ 判断方法：问自己「这个属性的值能在表中出现两次吗？」能出现两次就不能做主键

**失分点2：外键漏标**
❌ 1:N转换时把1端主键放到N端，但忘记标注「这是外键，引用XX表」
✅ 主键用下划线标注，外键用波浪线或写明REFERENCES

**失分点3：M:N联系属性放错位置**
❌ 把M:N联系的属性放到N端实体里
✅ M:N联系的属性必须放在独立的关系模式里

**失分点4：SQL中忘记写单引号**
❌ WHERE 书名 = 软件设计师教程
✅ WHERE 书名 = '软件设计师教程'（字符串必须用引号！考试中这个细节一旦漏写整道SQL零分）

### 🎯 UML类图6种关系·终极速记法

> ⚡ **核心口诀（背下来！）：** 「依赖用参数，关联存引用，聚合空心菱可分离，组合实心菱同生死，泛化实线三角是继承，实现虚线三角是接口」

**10秒内判断两个类的关系——五步排查法：**

拿到两个类A和B，按下面的顺序问自己（从强到弱）：

| 步骤 | 问自己 | 如果是→关系 | 画法 |
|------|--------|-----------|------|
| 第1步 | A「是一种」B吗？（A is a B？） | 泛化 | 实线+空心三角(A→B) |
| 第2步 | A「实现了」B接口吗？ | 实现 | 虚线+空心三角(A→B) |
| 第3步 | B「由」A组成，A没了B也没了？ | 组合 | 实心菱形+实线(B→A) |
| 第4步 | A「有」B，但B可以独立存在？ | 聚合 | 空心菱形+实线(A←B) |
| 第5步 | A的成员变量里有B的引用？ | 关联 | 实线 |
| 第6步 | A的方法参数/返回值里出现了B？ | 依赖 | 虚线箭头(A→B) |

**为什么按这个顺序？** 因为如果两个类既是泛化又满足关联——泛化优先级更高。从强到弱排查，找到第一个满足的就停下来。

### 🎯 UML类图6种关系·详细对比

> ⚡ **记忆锚点：**
> 聚合是空心菱形=可以分开（球队和球员——球队解散了球员还可以去其他队，就像空心菱形里什么都抓不住）
> 组合是实心菱形=同生共死（鸟和翅膀——鸟死了翅膀也没用了，就像实心菱形牢牢锁死）

**聚合 vs 组合（考试最爱考的区别！）：**

| 对比维度 | 聚合（空心菱形） | 组合（实心菱形） |
|---------|----------------|----------------|
| 核心比喻 | 球队和球员 | 人体和心脏 |
| 整体删除后部分？ | ✅ 部分可独立存在 | ❌ 部分随之消亡 |
| 部分能否属于多个整体？ | ✅ 球员可以转会 | ❌ 心脏只属于一个人 |
| 代码中体现 | B作为A的成员但外部创建 | B在A的构造函数中创建 |
| 考试关键词 | 「包括」「拥有」 | 「由...组成」「不可分割」 |

**关联 vs 聚合 vs 组合（三重境界）：**

- 关联（弱）：「老师知道学生」→ 只是有引用关系，没有「整体-部分」的语义
- 聚合（中）：「球队有球员」→ 整体-部分关系，但松散可分离
- 组合（强）：「人体有器官」→ 整体-部分关系，紧密同生共死

> 🎯 **考场判断口诀：「有关系→关联，整体部分→聚合，死活一起→组合」**

**泛化 vs 实现：**

- 泛化：「猫是一种动物」→ extends继承 → 实线+空心三角（子→父）
- 实现：「汽车实现了可驾驶接口」→ implements → 虚线+空心三角（类→接口）

🚨 **陷阱：不要把「实现」和「泛化」的三角方向搞反！** 三角永远指向「更抽象」的一方（父类/接口）。

### 🎯 UML用例图·include vs extend 秒杀法

用例图每年上午题必考1-2道，下午题也有填空题。核心难点就一个：include和extend怎么区分？

**一句话说清楚：**
- **<<include>>**：「每次都要」→ 执行用例A**必须**执行用例B。箭头指向被包含的用例。
- **<<extend>>**：「有时需要」→ 执行用例A**可能**执行用例B。箭头指向基础用例。

**强行记忆法：**
- include = 必须（include the mandatory step）
- extend = 可选（extend the optional step）

**考场关键字匹配：**
- 题干说「必须先...才能...」「总是需要...」→ include
- 题干说「可以选择...」「也可以...」「不必须...」→ extend

生活例子：
- 「取钱」<include>→「验证密码」——每次取钱都必须验证密码
- 「查询余额」<extend>→「打印凭条」——查完余额可以选择要不要打印

### 🎯 UML完整真题示例

**例题1：图书馆管理系统·类图**

题目描述：
"某图书馆管理系统中，有多种类型的文献（图书、期刊、论文），它们都有标题和编号。系统中记录读者的信息。一位读者可以借阅多个文献。借阅操作由管理员执行，系统会记录借阅时间。图书馆有多个阅览室，每个阅览室有一定数量的座位。"

请补充类图，填写缺失的类名和关系。

**解题过程：**

Step1【识别类】：
- 文献（抽象类——有子类图书/期刊/论文）→ 泛化关系：图书→文献、期刊→文献、论文→文献
- 读者（具体类）
- 管理员（具体类）
- 借阅记录（具体类——记录借阅时间和关系）
- 阅览室（具体类）
- 座位（阅览室的组成部分）

Step2【判断关系】：
- 图书、期刊、论文 和 文献 → **泛化**（是一种文献）
- 读者 和 借阅记录 → **关联**（读者知道自己借了什么）
- 文献 和 借阅记录 → **关联**
- 阅览室 和 座位 → **组合**（阅览室拆了，座位就不叫阅览室的座位了——实心菱形）
- 管理员 执行 借阅 → **依赖**（管理员的方法参数里有借阅记录）

Step3【画关系】：
```text
文献 <|—— 图书    （泛化，实线空心三角）
文献 <|—— 期刊
文献 <|—— 论文
借阅记录 —— 读者    （关联，双向或多向）
借阅记录 —— 文献
阅览室 ◆—— 座位   （组合，实心菱形在整体一侧）
管理员 - - -> 借阅记录（依赖，虚线箭头）
```

### 🎯 「如何读你从没见过的C代码」——4步战略

拿到一段没见过的C代码，不要慌。按这四步走：

**Step1【30秒】：看函数名和参数——猜这个函数是干什么的**

C语言函数名通常非常直白：
- `sort(int a[], int n)` → 排序（a是数组，n是个数）
- `search(int a[], int n, int key)` → 查找
- `reverse(char s[])` → 字符串反转
- `merge(int a[], int l, int m, int r)` → 归并
- `maxProfit(int p[], int n)` → 求最大利润（DP）
- `gcd(int a, int b)` → 最大公约数

参数名也有规律：
- `a` / `arr` / `data` → 数组
- `n` / `len` / `size` → 长度
- `l` / `left` / `low` → 左边界
- `r` / `right` / `high` → 右边界
- `m` / `mid` → 中间位置
- `key` / `target` / `x` → 查找目标

**Step2【1分钟】：找循环结构和终止条件——确定算法复杂度**

扫描代码中的关键字：
- 一个for循环，i从0到n-1 → O(n)
- 两个嵌套for循环 → O(n²)
- 循环每次折半/二分 → O(logn)
- 有递归调用 + 分治 → O(nlogn)

**Step3【2分钟】：找出变量更新规律——理解算法核心逻辑**

重点关注：
- 哪个变量在累加？→ 可能是求和/计数
- 哪个变量在取最大值？→ 可能是找最优解(DP/贪心)
- 哪个变量在交换位置？→ 可能是排序/反转
- 哪个变量在向某个方向移动？→ 可能是双指针

**Step4【5分钟】：用题目给的示例数据「走一遍」代码**

把题目给的示例数据代入代码，用手工模拟一遍。这一步最关键——可以帮你检验填空是否正确。

### 🎯 算法题五大常见模式及解题模板

**模式1：分治（归并排序/快速排序）**

识别特征：
- 函数名含 merge/quick/divide
- 代码中有 pivot 或 mid
- 有递归调用两次

填空规律：
- 递归终止条件（`if(low >= high) return;`）
- 分界点（`mid = (low + high) / 2`）
- 合并操作的位置

**模式2：动态规划（最长公共子序列/背包问题）**

识别特征：
- 有二维数组 dp[][] 或一维数组 dp[]
- max() 函数频繁出现
- 有双层循环

填空规律：
- dp数组的初始化（第一行/第一列通常填0）
- 状态转移方程的核心代码（if条件判断+dp取值）
- 最终结果取dp[n][m]或dp[n]

**模式3：贪心（活动选择/哈夫曼）**

识别特征：
- 先排序再处理
- 每次选「最小的」「最大的」「最早的」
- 变量名可能叫 greedy/select/schedule

填空规律：
- 排序函数调用
- 选择条件的判断
- 累加结果的代码

**模式4：双指针（数组去重/反转）**

识别特征：
- 两个变量 i 和 j（或 left 和 right）
- 一个从前往后，一个从后往前
- 或者快指针和慢指针

填空规律：
- 初始化 i=0, j=n-1
- while(i < j)循环条件
- 指针移动的代码

**模式5：回溯（迷宫/八皇后）**

识别特征：
- 有递归 + 循环组合
- 有「尝试→失败→回退」的模式
- 可能用到 visited[] 数组

填空规律：
- 递归终止条件（找到解/走不通）
- 标记访问 `visited[i] = 1`
- 回退 `visited[i] = 0`

### 🎯 算法题填空题的5步填法

**Step1：第一个空通常最简单——初始化变量**

90%的算法题第一个空是：
- `i = 0` 或 `j = 0`
- `count = 0`
- `result = 初始值`
- `dp[0] = 某个基值`

> ⚡ **如果第一个空你卡住了——问自己：这段代码运行前，什么变量的值还没设置？**

**Step2：看空后面的代码——倒推空要做什么**

空后面的代码用了什么变量？那个变量在空之前声明了吗？没有→空就是初始化这个变量。

**Step3：看循环条件——循环要做什么、到哪停止**

如果循环是 `for(i=0; ____; i++)` → 填空大概率是 `i < n` 或 `i < len`

**Step4：看if条件——条件要判断什么**

if语句的条件通常是：
- `a[i] > a[j]`（比较大小）
- `a[i] == key`（查找目标）
- `dp[i][j] > max`（更新最大值）

**Step5：用示例数据验证——最关键的一步！**

把你填的代码代入题目给的示例数据，手工跑一遍。如果输出不对，说明填空有误。

### 🎯 「如果考试中我慌了怎么办」——紧急应对指南

**场景1：上午题做到一半发现很多题不会**
→ 不是你真的不会，是你太紧张导致大脑一片空白。
**应对：** 深呼吸3次（吸4秒-停2秒-呼6秒）。跳过当前这道题，做下一道。做出3道「送分题」（循环队列判空、排序性质对比等）找回信心后再回头看。

**场景2：下午题第一道DFD就蒙了**
→ 不要死磕。DFD是下午题最简单的，你现在做不出来只说明你被第一眼的陌生感吓到了。
**应对：** 先跳过DFD，做第二道数据库。做完数据库后再回头看DFD——这时候大脑已经进入「做题模式」，陌生的感觉消退了。

**场景3：时间快到了还剩一道题没做**
→ 30秒内决定：放弃还是抢分？
**应对方案A（放弃）：** 这道题完全没思路 → 果断放弃，把时间用来检查前面做过的题（检查比你胡乱抢答更有效）
**应对方案B（抢分）：** 这道题会做但没时间写了 → 快速写字，只写关键步骤和答案，跳过中间推导过程——给分主要看最终答案对不对

**场景4：旁边人翻卷子特别快，你慌了**
→ **永远不要关注别人的速度。** 翻得快可能因为：他也不会做在乱翻 / 他直接跳到后面做 / 他放弃了在翻着玩。
**应对：** 告诉自己「我的节奏就是对的」，继续按自己的步调做题。你做出来的题比别人翻过的题更有价值。

### 🎯 算法题·进阶实战：用示例数据验证填空

**实战演示：用一道真题级别的算法题展示完整解题过程**

假设你在考场上遇到以下代码（经典的分段反转题）：

```c
// 函数功能：反转链表中从第 m 个到第 n 个结点之间的部分
// 参数：head-链表头指针, m-起始位置, n-结束位置(1≤m≤n≤链表长度)
struct ListNode* reverseBetween(struct ListNode* head, int m, int n) {
    if (head == NULL || m == n) return head;
    
    struct ListNode dummy;
    dummy.next = head;
    struct ListNode *pre = &dummy;
    
    // 第一步：找到第 m 个结点的前驱
    for (int i = 1; i < m; i++) {
        pre = ______________;  // 空①
    }
    
    // 第二步：反转从 m 到 n 的结点（头插法）
    struct ListNode *cur = pre->next;
    for (int i = m; i < n; i++) {
        struct ListNode *temp = cur->next;
        cur->next = ______________;  // 空②
        temp->next = pre->next;
        pre->next = ______________;  // 空③
    }
    
    return dummy.next;
}
```

**解题过程（完整展示思路）：**

**Step1：看函数名和参数（30秒）**
- 函数名 `reverseBetween` → 「在某范围内反转」，看到 reverse 就知道和反转有关
- 参数 `m, n` → 反转的起止位置
- `head` → 链表头指针（考的是链表操作！）

**Step2：找循环结构和用途（1分钟）**
- 第一个for循环：`i=1; i<m; i++` → 这是在链表上移动，移动到第m个位置之前
- 第二个for循环：`i=m; i<n; i++` → 处理从m到n-1的结点（因为是头插法，每次处理一个）

**Step3：填空（3分钟）**

空①分析：循环的用途是让pre走到第m-1个结点（第m个的前驱）
- 每次循环pre要往后移动一个结点
- 链表上移动一个结点 = `pre = pre->next`
- 答案：`pre->next`

空②分析：cur->next需要断开原来的连接
- 因为是反转，cur的next应该指向"被反转部分"的后面（即temp的下一个）
- temp = cur->next，那temp后面是temp->next
- 答案：`temp->next`

空③分析：pre->next需要更新为"新插入到头部的结点"
- 在头插法中，temp结点被插到pre后面（即成为反转部分的新头部）
- 所以pre->next = temp
- 答案：`temp`

**Step4：用示例数据验证（2分钟）**

假设链表 1→2→3→4→5, m=2, n=4（要反转2→3→4成4→3→2）

初始：dummy→1→2→3→4→5, pre指向1
空①填 `pre->next`：pre最终指向1（第2个的前驱, 即第1个）
cur = pre->next = 结点2

第一轮（i=2）：temp=3, cur->next=temp->next=4, temp->next=pre->next=2, pre->next=temp=3
链表变成：1→3→2→4→5

第二轮（i=3）：cur还是指向2, temp=cur->next=4, cur->next=4->next=5, temp->next=pre->next=3, pre->next=temp=4
链表变成：1→4→3→2→5

结果正确！m=2到n=4的部分（2→3→4）反转成了（4→3→2）。

> 🎯 **回顾整个解题过程：** 你看，这道看起来很难的算法题，本质上只考了3个知识点——链表遍历（空①）、链表断开（空②）、头插法（空③）。如果你练过阶段一的链表操作（insert/delete/reverse），这三个空都不是新知识，只是换了个包装。

### 🎯 选做题（Java）·设计模式补全代码的通用套路

如果你选了Java作为下午选做题（强烈推荐！），以下是出题率最高的3种设计模式及其补全代码规律：

**套路1：单例模式（出现频率★ ★ ★ ★ ★）**

```java
public class _____ {  // 空①：填类名（通常题干已给出）
    private static _____ instance;  // 空②：填「类名」
    
    private _____() {}  // 空③：填「类名」——构造器私有！
    
    public static _____ getInstance() {  // 空④：填「类名」（返回类型）
        if (instance == null) {
            instance = new _____();  // 空⑤：填「类名」
        }
        return instance;
    }
}
```
> ⚡ **规律：** 所有空都是同一个类名！单例模式就是「类名填空大赛」——看到 private static X instance + private X() + public static X getInstance() → X就是同一个类名。

**套路2：工厂方法模式**

```java
// 抽象产品
interface Product { void use(); }

// 具体产品
class ConcreteProduct implements Product {
    public void use() { System.out.println("使用产品"); }
}

// 抽象工厂
abstract class Factory {
    abstract ________ createProduct();  // 空①：填「Product」（返回抽象产品类型）
}

// 具体工厂
class ConcreteFactory extends Factory {
    ________ createProduct() {  // 空②：填「Product」
        return new ________();  // 空③：填「ConcreteProduct」（创建具体产品）
    }
}
```
> ⚡ **规律：** 返回类型填「抽象产品接口名」→ Product；new后面填「具体产品类名」→ ConcreteProduct。

**套路3：观察者模式**

```java
interface Observer {
    void update(________);  // 空①：填「String message」或「Subject s」（看题干描述）
}

class Subject {
    private List<________> observers = new ArrayList<>();  // 空②：填「Observer」
    
    public void attach(________ o) { observers.add(o); }  // 空③：填「Observer」
    
    public void notifyObservers() {
        for (________ o : observers) {  // 空④：填「Observer」
            o.update(message);
        }
    }
}
```
> ⚡ **规律：** 所有存观察者、遍历观察者的地方都填「Observer」！观察者模式就是「Observer类型填空大赛」。

### 🎯 上午题选择题的技巧体系（考试当天救命用）

**排除法的三层过滤：**

第一层【绝对错误】→ 直接划掉
- 出现了你确定不对的术语（比如问TCP却说「无连接」）
- 数值明显不合理（比如问子网可用IP说255个——不可能，要去掉网络号和广播地址）
- 概念方向反了（比如问栈的特点说「先进先出」）

第二层【值域矛盾】→ 快速排除
- 4个选项中有2个互相矛盾 → 答案在矛盾的两个中
- 4个选项中有1个和其他3个语义不同类 → 大概率排除那个异类

第三层【口诀匹配】→ 直接秒选
- 看到「稳定排序」→ 脑海里弹出口诀「基冒入归」，选项谁在这个列表中谁就是对的
- 看到「需求不确定」→ 原型或敏捷
- 看到「每次都要...」→ include

**不会的题怎么猜（概率最大法）：**
- 数值计算题：选中间值（出题人通常不会把极端值作为正确答案）
- 概念判断题四个中如果有两个表述相似：选那两个中的一个
- 绝对化词语（一定/必须/全部/永远）→ 通常不是正确答案（计算机科学中很少有绝对的）
- 「通常」「一般」「主要」等保守措辞 → 是正确答案的概率反而高
