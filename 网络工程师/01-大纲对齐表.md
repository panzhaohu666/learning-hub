# 大纲对齐表

本表的作用：把《网络工程师考试大纲》（2024 年审定通过）的每一条，对照到「本仓库现有内容 / 需要新增 / 材料从哪来 / 是否已核对」。

**这张表是全套计划的地基。** 正文能不能写、写到什么深度，全部以这张表为准；表里标「待核」的，正文就不许动。

---

## 0. 一个必须先说明的问题：大纲版本存在转述冲突

我查到的三份公开转述，在**两处结构性问题**上互相矛盾：

| 争点 | 版本 A（希赛 / 信管网 / 百度百科） | 版本 B（51CTO 转载） |
|---|---|---|
| 科目一（计算机与网络知识）模块数 | **7 个**：计算机系统 / 系统开发运行 / 网络技术 / 网络安全 / 标准化 / 信息化 / 专业英语 | **8 个**：以上 7 个 + 「网络新技术：云存储、物联网、网络管理虚拟化、软件定义网络」 |
| 「网络新技术」归属 | 放在**科目二**第 4 章（光纤网 / 无线网 / 主干网 / 通信服务 / 网络管理） | 科目一第 5 章 + 科目二第 4 章**都**有 |
| 网络安全是否含 UTM、IDS/IPS | 版本 A 的希赛稿无；百度百科无 | 版本 B 含「4.3 UTM 安全网关、4.4 IDS、IPS」 |
| 是否含「3.9 存储域网络（FC-SAN / IP-SAN）」 | 无 | 有 |

**判断：** 版本 A 三源一致，且与「科目一 7 个知识模块 + 科目二 3 大块」的通行说法吻合，本表按版本 A 搭。但版本 B 指出的「网络新技术」很可能是 2024 版相对旧版的新增内容——旧版大纲确实没有 SDN/云存储这些。

**处理方式：** 本表把版本 B 独有的条目单独列入「§X 争议条目」并标 **⚠️ 待核**。**在拿到官方大纲正文之前，这些条目既不写正文、也不排除。** 核对办法见文末「怎么核对」。

## 3. 覆盖度总账

以大纲条目计（按版本 A 的 7+3 结构）：

| 状态 | 条目数 | 占比 |
|---|---|---|

**结论：本仓库现有内容对网络工程师的覆盖约 6%–41%（按宽松口径），主干中的主干——科目二的规划与配置——是 0。** 旧方向的 `软件设计师/` 一万七千行，对这场考试的有效贡献接近零：软件设计师考数据结构、算法、UML、设计模式，网络工程师一个都不考。

## 4. 怎么核对（拿到官方大纲后照做）

1. **买或借《网络工程师考试大纲》（2024 年审定通过）**，ISBN 9787302668848，工信部教育与考试中心编。这是唯一权威源。
2. 翻到「二、考试范围」，逐条比对本表 §1 的每个条目：
   - 表里有、大纲没有 → 删掉该行
   - 大纲有、表里没有 → 新增该行并标 ❌
3. 重点核 §X 争议条目那 6 项，逐项判定「有 / 无」。
4. 核对完毕后，把本文件顶部「版本」一行改为「已对官方大纲核对（日期）」，并把所有 ⚠️ 待核替换为确定状态。
5. **只有完成以上步骤，才允许开始写各章正文。**
